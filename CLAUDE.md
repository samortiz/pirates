# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Overview

Corsairs of the Shattered Sea: a top-down medieval pirate naval game in plain browser JavaScript (canvas, no build step, no frameworks), plus a Node multiplayer server with **zero npm dependencies** (it has its own RFC 6455 WebSocket implementation in `server/server.js`). Requires Node 18+. There is no test suite, linter or bundler.

## Running

```sh
npm start                 # server on http://localhost:8080 (binds 127.0.0.1 only)
npm run lan               # bind 0.0.0.0, prints LAN addresses
npm run tunnel            # also spawns a cloudflared quick tunnel and prints a public trycloudflare.com link
PORT=8081 npm start       # another port (the server exits with a hint if the port is taken)
```

Single player also works by opening `index.html` directly from disk (`file://`); multiplayer is only offered when the page is served over http(s) (`Net.available()`). `cloudflared` is looked up at `$CLOUDFLARED`, `~/.local/bin/cloudflared`, `./bin/cloudflared`, then `PATH`.

## Architecture

**Script loading.** `index.html` loads `js/*.js` as classic scripts in a fixed order (`core → ship → battle → view → net → lands → world → quests → main`). Everything is a global `const`/`class`; later files depend on earlier ones. Adding a file means adding a `<script>` tag in the right position.

**Simulation vs. presentation split — the key invariant.** `core.js`, `ship.js` and `battle.js` are also executed on the server: `server.js` reads them and runs them inside a `vm` context (sandbox has only `console`), then pulls out `Battle`, `Ship`, `SHIP_CLASSES`, `SHIP_NAMES`, `AMMO`, `STANCES`, `pick`, `clamp`. Consequently:
- `battle.js` must stay free of drawing, sound and DOM. It communicates visible effects through `battle.emit()` → `battle.events` (events with a `to` field are private to one ship's player).
- `core.js` and `ship.js` may *define* DOM/canvas/audio code (`Input`, `Sfx`, `UI`, `Ship.draw`) but nothing on the simulation path may *call* it, and top-level code in them must not touch `window`/`document`.
- If the server needs another symbol from these files, add it to the `vm.runInContext('({ ... })')` export list in `server.js`.

**Ship control.** Every ship (human or AI) is driven through `ship.ctrl = { rudder, sail, ammo, stance, acts[] }`. AI writes `ctrl` itself; `readBattleKeys()` in `view.js` writes it from the keyboard in single player; in multiplayer the client sends `in`/`act` messages and the server writes `ctrl` after validating them. Ships whose player disconnects are handed to the AI.

**Rendering.** `BattleView` (`view.js`) draws anything shaped like a Battle (`{ ships, wind, R, grapples, t }`). In single player that is the live `Battle`; in multiplayer it is a mirror that `Net` (`net.js`) builds from server snapshots and interpolates between them.

**Multiplayer is server-authoritative.** The server ticks the battle at 30 Hz and sends snapshots at 15 Hz. Snapshot ships are positional arrays (`sendSnapshot()` in `server.js`) decoded by index in `Net.snap()`. `STATE_CODES` is duplicated in both files and ammo is encoded as an index into `Object.keys(AMMO)`, so changing a ship field, state or ammo type means updating both sides together. Client message types are `hello`, `set`, `addAI`, `delAI`, `start`, `in`, `act`; the server sends `welcome`, `lobby`, `note`, `start`, `snap`, `end`. The first named player is host (only the host can add/remove AI and start). There are two teams (0 Red Banner, 1 Black Banner).

**Campaign (single player only).** `world.js` holds the overworld map (islands, ports, NPC fleets via `genFleet`) and `Campaign`. `main.js` holds the `Game` object: the title screen, docking and port menus (`Game.dock` renders one district tab at a time from its `districts` list: Docks/market, Tavern/crew and notice board, Shipwright/repairs, refits and powder, Shipyard/ships and fleet, Guild hall, Holdings; keys 1–6, last tab kept in `Game.portTab`), save-slot menus (`slotMenu`, `nameVoyage`, the in-game `logBook` on L, fleet orders on F), encounters, starting and finishing battles, and the main `frame(dt)` loop.
- **Map.** The overworld is a world map the whole way round (180°W–180°E, 78°N–60°S, so ships can round Cape Horn) that **wraps east–west**: `WRAP_W` (core.js, set to `WORLD.W` by world.js; 0 in battles and on the server) drives `wrapDx()` (an x difference the short way round), `wrapX()` and the wrap-aware `dist()`. Compare overworld x positions only through these, never with a bare `a.x - b.x`. The player's x is never wrapped (the view follows her); `WorldMap.nearYou()` keeps each NPC fleet on the side of the world nearest her; ports, quests, treasure and wrecks stay in `[0, WORLD.W)`. `WorldMap.draw` draws a copy of the world (`drawWorld`: land, ports, `Quests.drawSea`) for each world-width in view, and the corner chart scrolls to keep the player centred (`Quests.drawChart` gets a `cx(x)` function). `landSd`, `navIdx`, `clearLine`, `findPath` (waypoints run on without a jump across 180°) and `navSteer` all wrap. Outlines may run past 180° (Eurasia goes on to Chukotka); they are rasterised a world away too, so no two outlines may cover the same land. `WORLD.W` must stay a multiple of `LAND.R` and `NAV.cell`. `lands.js` holds `LANDS`: coastlines as `[lon, lat, …]` outlines, or `isle: [lon, lat, r]` for small islands. Narrow straits are deliberately widened so NPCs can route through them. The Northwest Passage is not a cut: it is open water between North America's Arctic shore, a chain of island outlines and the Queen Elizabeth Islands, which run off the top of the map. `lands.js` also holds `WATERS`: rivers, the Panama Canal, the St Lawrence and each of the Great Lakes with the short rivers between them (one cut each, overlapping where they meet; the lakes are enlarged and pushed apart), the Red Sea with the Suez Canal, the Persian Gulf, the Bosporus/Dardanelles and the Kerch Strait into the Black Sea and Azov (the Black Sea itself is an inlet in the Eurasia outline), the Strait of Georgia behind Vancouver Island, Cook Inlet, and the Bohai with the Hai River up to Beijing, each a centre line from its mouth with a width in px (`w`, `[mouth, head]`, or `ws`, one per point) and an optional routing `pad`. Rivers with a port at the head are wide enough (about 100 px, pad 12) for `NAV` to route up them. `world.js` projects everything with `geo(lon, lat)` (`GEO` px per degree), roughens the edges, rasterises the lands, carves the `WATERS` out of them (`LAND.cuts`; `LAND.cut`/`inCut()` give the cut's index + 1) and builds `LAND.sd`, a signed distance field. `landSd()`, `onLand()`, `landNormal()` and `pushOffLand()` all read it. `drawLand()` strokes only the coast chunks and river banks (`LAND.banks`) in view, and clips the cuts out of the land with one even-odd clip, `drawLand` clips each cut out separately, so `WATERS` may overlap each other, but one part of a channel must not overlap another (tight bends are fine: `unloop` snips the folds out of a bank). A cut with `hide: true` (a strait through a filled-in coast) hides even short stretches of land outline inside it from the coast stroke. Long stretches of a land outline that lie inside a cut (Africa and Arabia under the Red Sea) are left out of the coast stroke. In a cut, `NAV` keeps the cut's `pad` off the banks instead of `NAV.pad`. Open water the first port can't reach (lakes, river reaches too narrow for routing) is blocked in `NAV`; use `seaOK()` to test a spawn point. The player can still sail up those river reaches; NPCs can't. After editing `LANDS` or `WATERS`, check that every port's departure point (`sx/sy`) is `seaOK` and that `findPath` connects them. Ports are given as `lon/lat` plus `ang`, the bearing out to sea. `portDist()` is the cached sea-lane distance between ports (used for job deadlines). NPC counts go through `seaFill()`, which scales them by `NAV.water`. Saves carry `mapVer`: a save from a map listed in `MAP_SHIFT` (same coasts, different projection origin) has every position shifted (`Campaign.shiftMap`); any other `MAP_VER` mismatch moves ships back to port and re-charts treasure (`Campaign.newMap`). The Pacific ports (Panama … Anchorage), the East Indies ports (Malacca … Nagasaki), then the Great Lakes, Cathay/Korea/Japan, river-head and Australia/New Zealand ports (Montreal … Christchurch), then the Mediterranean, American Pacific, Persian Gulf and Black Sea ports (Athens … Mariupol) come last in `PORTS`, because saves refer to ports by index: add new ports at the end, and replace a removed port in place rather than deleting it (Chicago and Kuwait sit where Toronto and Detroit were, Anchorage where Sitka was, New York where Jamestown was, Dublin and New Orleans where Sydney and Adelaide were, and Odesa and Mariupol moved up into Hobart's and Wellington's places). When indices must change, bump `PORT_VER` and add a `PORT_MOVES` entry (old index → new port name); `Campaign.movePorts()` renumbers every port index in a save (hq, props, consign, banned, seize, quests, fleet and dock ships' `at`/tasks), merging what lands in one port. A port on a river or lake has `near: 30`, so its departure point is searched from 30 px out (mid-channel) instead of 70. Dublin lies at the head of a widened Irish Sea cut. Port goods follow history (Caribbean sugar and tobacco, Spanish American silver and gold, Guinea gold and ivory, Indian spice, cloth and tea, Levant silk and coffee). Each port's `price` is a base multiplier; the actual plunder price comes from `plunderPrice(port, day)`, which swings over game days (one day per 25 s at sea).
- **Saves.** There are 5 named slots in `localStorage` under `corsairs-shattered-sea-slot-<i>`, each holding `{ name, time, s }`. Each slot also has a separate autosave under `<key>-auto`: `Campaign.save()` is the autosave (dock, battles, treasure) and only writes that key, while `Campaign.saveManual()` (log-book Save, Save as, Save & quit, a new voyage) writes the manual key. Autosaves must never overwrite a manual save, and loading writes nothing. `Campaign.latest()` returns `{ i, auto }` for the newest save of either kind. The pre-slot key `corsairs-shattered-sea-v1` is migrated into slot 0 once. Saves record `mapScale`, and `load()` rescales the ship position if `MAP_SCALE` has changed.
- **Trade and jobs.** `GOODS` (world.js) lists trade goods. Each port `makes` some (cheap) and `wants` others (dear), and prices come from `goodPrice()`/`buyPrice()`. The player's hold is `s.hold = { good: crates }`; use `holdUsed`/`stow`/`trimHold`. `plunder` can't be bought, and `contraband` (hidden) exists only for smuggling jobs. `quests.js` holds `Quests`: notice-board jobs in `s.quests` (deliver, courier, bounty, recover, escort, smuggle, marque), prisoners for ransom, dock work, tribute, treasure maps (`s.maps`), wreckage/flotsam, fishing, and patrol searches. It is called from `WorldMap` (`update`, `drawSea`, `drawChart`, `label`, `spawnQuest`) and from `Game` (`onDock`, `boardHtml`, `portAct`, `afterBattle`, `onDefeat`). Jobs that involve a ship store its fleet in the quest and respawn it in the `WorldMap` constructor, because NPCs aren't saved. `Quests.ensure()` fills in missing fields on old saves.
- **Careers.** `s.career` is `'pirate'` or `'merchant'` (chosen in `Game.chooseCareer` for a new voyage; old saves default to pirate). Use `isMerchant()`. Merchants get better prices (`goodPrice`/`buyPrice`), aren't hunted by hunters (`WorldMap.hostileTo`/`aggroOf`), and earn guild standing `s.trade` through `addStanding()` (honest goods sold, jobs via `Quests.merit`, beating pirates); `s.guild` is set at `GUILD_GOAL`, the merchant's win, while the Admiral boss is the pirate's. Attacking a non-hostile ship without a marque calls `Game.turnPirate()`; a pirate buys a pardon (`pardonCost`) in the port's Guild hall. `renown()` (max of fame and standing) sets NPC strength.
- **Fleet.** `s.fleet` (world.js: `SHIPYARD_PORTS`, `FLEET_MAX`, `newFleetShip`, `fleetReady`) holds ships that sail in the player's wing and fight beside the flagship, each with its own `hull`, `sailHp`, `crew` and `ammo` stock. They are bought at full class price only at a shipyard port, start with no crew, and join a battle only once a quarter of their berths are filled. Any port can repair, man, rearm or sell them (`Game.fleetAct`). `Game.settleFleet()` writes battle damage back after a battle. If the flagship is lost, the best surviving fleet ship becomes the new flagship. `ensureFleet()` converts the old `s.escorts` in saves from before fleets existed.
- **Holdings and HQ.** `s.props[pi]` (world.js: `PROP_INFO`, `propsOf`, `ownsAt`) holds property bought in a port: `bank` (`{ gold, day }`, interest added lazily by `bankSettle()` on docking), `ware` (`{ good: crates }`, up to `WARE_CAP`) and `dock` (laid-up fleet ships, up to `DOCK_CAP`, not counted in `s.fleet` or against `fleetMax(s)`). All of it is safe on defeat but reachable only in that port. `s.hq` is the headquarters port (needs property there, `HQ_COST`): it adds `HQ_FLEET` to `fleetMax(s)` (use that, not `FLEET_MAX`), lets the Holdings district command every detached ship (`Game.admiraltyHtml`, `routeMenu(f, null)` starts a route for a ship at sea), and is where a captain with no fleet left washes up, taking the best ship in its dock. Holdings actions are `pp*` in `Game.holdAct`.
- **Gold, purses and fame.** Gold is never pooled: `s.gold` is what is aboard the flagship (half of it goes down if she sinks), counting houses hold their own, and every fleet ship has a purse `f.gold`. Route ships buy and sell out of their purse (`sellCargo`/`routeTrade`) and, at a stop with your counting house, bank what's above `task.float` or draw up to it; wing ships hand their purse over with `takePurse()` (on docking, rejoining, selling, laying up). Fame shown and used everywhere is `fameOf(s)` = `s.fame` (deeds) + `wealthFame(s)` (1 per `WEALTH_PER_FAME` of `worth(s)`: gold, banks, purses, consignments, owned ships); `pardonCost` uses deeds only.
- **Ships for hire.** Hired ships live in `s.fleet` with `f.hired = { kind, rate, until? }` (world.js: `hireOffers`, `hiredShip`, `HIRE_MAX`, `FREIGHT_MAX`). Use `ownFleet(s)`/`ownWing(s)` wherever only ships you own count (fleet size, orders, selling, lay-up, flagship succession, worth). Escorts sail in the wing, fight (not `commandable`), are mended free on docking and leave at `until`. Freighters get task `{ type: 'freight', to, from }`, sail as `'own'` NPCs, and on arrival `deliverFreight()` puts gold in the bank and goods in the warehouse there, the rest in `s.consign[pi]`, collected by `collectConsign()` on docking. UI is `Game.hireHtml`/`hireAct`/`charterMenu` in the Shipyard district.
- **Squadrons and trade routes.** A fleet ship with `f.task` set is detached: it sails the map alone as an overworld NPC of kind `'own'` (`WorldMap.syncOwn` creates/removes these from `s.fleet` every frame, `ownStep` drives them), and its position lives in `f.x/f.y/f.heading` so it is saved. Tasks are `station` (sail to a port and wait), `route` (`stops`, `leg`, `profit`, `trips`: at each stop `routeTrade()` sells `f.cargo` and buys the best-margin good for the next stop out of her purse `f.gold`), and `recall` (sail to the player and rejoin). `f.at` is the port she lies in. Only wing ships (`inWing`/`wingFleet`) follow the player and fight in battles; port services work only on ships that are `fleetHere(f, pi)`. Orders are given in the Shipyard district (station here, trade route…, join, recall) and at sea with F (`Game.fleetOrders`). Pirates raid laden route ships at sea (`raidOwn`).
- **Overworld NPCs** are not `Battle` ships. Each is a plain object (`kind`, `fleet`, `info` from `NPC_INFO`, waypoint/cooldown state) that sails as `n.ship`, a `Ship` of its lead fleet entry built by `npcShip()`. `WorldMap.update` picks a target heading (chase, raid, flee, waypoint, steer around islands, tack when upwind) and drives `n.ship` through rudder and sail and `Ship.update`, so NPCs obey exactly the same wind and handling physics as the player's ship (class speed and turn, the fleet entry's `speedMul`, and `OVERWORLD_SPEED` for every ship on the map). `n.x/y/heading` are copied back from `n.ship` each tick. Routing goes through `navSteer()` (world.js): a `NAV` grid of open water (blocked within `NAV.pad` of any coast), `clearLine()` for straight runs, and A* `findPath()` with string-pulling, limited to `NAV.budget` re-plans per frame. Coasts come from `landSd()`, which drawing, grounding and port placement all share. Fleet followers (`followWing`) fall into line astern along the lead's `wakeTrail` when land blocks their V-formation slot. Anything that rebuilds an NPC's ship (e.g. after a battle in `main.js`) must use `npcShip()`. `ChartView` (C at sea) is a full-screen chart of land and ports with no ships; the world is paused while it is open. The player's ship gets a gold ★ name label at sea and a gold heading arrow with a pulsing ring on the corner chart (`WorldMap.draw`). Pirates are regional and territorial: they spawn in `PIRATE_GROUNDS` (Caribbean, Arabian Sea, East Indies, …), never in `PATROLLED` seas, keep a `n.lair`, cruise within `PIRATE_RANGE` of it (`nearLair`), and give up a chase after `PIRATE_CHASE` s or `PIRATE_LEASH` px from home. Pirates carry real goods (`localGood`: what nearby ports make), and raids add the victim's goods to their holds with `stowHaul`; `plunder` survives only so old saves can sell it. Pirates not chasing the player hunt merchants (`canRaid`: not cog-led, cooldown, at most 2 raids) and take half their loot in `raid()` without a battle. Fleet entries from `genFleet` become `Ship` options when a battle starts, so flags such as `noFlee` (pirates and hunters fight to the death: no fleeing, no striking colours, no yielding when boarded) live there. Dialogs are HTML strings passed to `UI.show(html, handler)`. Buttons use `data-a` for the action and `data-k` for a keyboard shortcut, and `class="primary"` marks the button Enter presses. Escape user-supplied text with `esc()`.

**Game data.** Ship classes, ammo types, colour styles and name pools are tables at the top of `core.js`. Server-side input validation checks against these tables.

**Armament and collisions.** `GUNS` (core.js) is the broadside battery (`culverin`, `rifled`, `bombard`, `flame`): multipliers on the loaded `AMMO`, except that a `fire` battery throws `FIRE_SHOT` whatever is loaded. `BOW_GUN` is an optional forward-firing chaser (act `'F'`, key R, `reload.F`), `RAM` an optional ram. A ship's fittings are `{ gun, bow, ram }` (`fitOf()`), stored on `s.ship`, fleet and dock entries and NPC fleet entries (`armNpc()` in world.js), and passed to `new Ship()`; carry them with `...fitOf(x)` wherever a campaign ship object is rebuilt. Use `ship.shot(ammo, side)` for a gun's real range/damage and `ship.reloadTime(side)`. All harm goes through `Battle.hurt()`; burning (`ship.burn`, seconds left) ticks in `burnStep()`, and hull contact damage is `Battle.collide()` (closing speed × mass ratio, ram bonus bow-on, one blow per pair per 1.2 s, emits `ram`). The snapshot ship array ends with `reload.F` and `burn`; `start` carries `gun/bow/ram`.

## Server security constraints (keep these when editing `server.js`)

- Only the files in the `FILES` map are served: `index.html`, `style.css` and `js/*.js`. Don't add generic static-directory serving.
- Bind to `127.0.0.1` unless `--lan` is passed.
- Every client message is validated and clamped, and is rate-limited to 120 messages/s. The limits are 8 players, 10 AI ships and a 16 KB WebSocket frame. Never trust client-sent positions or state. Clients only send orders.
